# ROUTE B — The complete plan to "functions and looks exactly like the original"

> **The contract.** When every checkbox in this document is green, the modern
> build is behaviorally and visually indistinguishable from VICEROY.EXE run in
> DOSBox, proven by the acceptance gates in Phase 7 — byte-identical save
> exchange, pixel-identical frame matrix, same-seed determinism parity.
> There is no Phase 8. Anything discovered mid-phase belongs to one of the
> four enumeration sources below, all of which are FINITE and MACHINE-LISTED
> today. Discovery can move work *between* phases; it cannot add scope.

---

## 0. Why nothing new can appear (the completeness mechanism)

Every past "oh wait, there's more" came from hidden scope becoming visible at
a call site. That cannot recur, because the work below is bounded by four
closed, machine-enumerated inventories that already exist in this repo:

| # | Enumeration source | Size | Where |
|---|---|---:|---|
| E1 | RTLink thunk table (every cross-segment call that exists) | 1,020 entries / 777 lib-referenced stubs | `re_work` thunk scan → `docs/THUNK_WIRING.md` |
| E2 | Link-gap symbol census (every undefined symbol in the lib) | 184 func bodies + 739 named + 14 mixed | `docs/LINK_GAP.md` (regenerated by `tools/linkgap.py`) |
| E3 | Screen-entry map (`enter_screen_view(id)` call sites) + GAME.TXT `@BEGINMENU` tree | 6 ids + menu tree | `docs/SCREEN_LAYOUTS.md`, `docs/OPENING_SEQUENCE.md` |
| E4 | The function census itself | 1,248 functions, 100% bounded | `re_work/functions.json` |

**Terminal states.** Every item in E1–E4 must end in exactly one state:
- **PORTED** — byte-verified C in the build, or
- **WIRED** — linker alias to a ported function, or
- **UNREACHABLE(proof)** — a recorded call-graph proof that no gameplay path
  reaches it (e.g. dead debug/EMS/serial leaves), checked by `tools/audit.py`.

The plan is done when no item is in any other state AND the Phase-7 gates
pass. That is the whole definition. No vibes, no "almost".

**Standing rule for estimates.** 1 session = one focused multi-hour working
pass. Ranges are honest, not padded.

## Phase 0 — Build the proof rigs FIRST (2 sessions)

Nothing else lands until the thing that catches divergence exists. These rigs
are the difference between "I believe it matches" and "it matches".

- [ ] **0.1 Determinism rig.** Scripted-input driver for the modern build
      (keystroke playback file → input queue). The original's RNG is the MSC
      6.0 LCG (`rand` @0x0103D4, ported) — seed it explicitly. Gate output:
      a save file. The same script must be replayable against DOSBox via its
      keystroke mapper (one-time setup, documented).
- [ ] **0.2 Save-diff gate.** `tools/savediff.py`: byte-compare two COLONIZE
      saves, with a cataloged allowlist of legitimately-divergent bytes
      (timestamp fields only — the catalog itself is part of the deliverable;
      target allowlist size: < 8 bytes).
- [ ] **0.3 Pixel rig.** Checkpoint screenshot protocol: F12 PPM in the
      modern build vs DOSBox 0.74 screenshot at the same defined states;
      `tools/pixdiff.py` asserts byte-equal 320×200 frames after palette
      mapping. Checkpoint list = one frame per screen id in E3 × defined
      states (enumerated in Phase 7.1).
- [ ] **0.4 Re-baseline the soak.** `--smoke=60` and `--smoke=500` re-run now
      that AI19 commits real moves; record the new state trace as the
      regression baseline (replaces the stub-era 2026-06-10 baseline in
      `docs/INTEGRATION_STATUS.md`).

**Dependency (user):** original COLONIZE install files + a working DOSBox with
the same files, for capture. Nothing is committed (gitignored, per the
standing copyright rule).

## Standing rules (unchanged, restated as part of the contract)

1. VICEROY.EXE, game data, and DOSBox captures are NEVER committed
   (gitignored); the modern build embeds no original bytes.
2. Every ported value cites a file offset; nothing is invented. Where the
   original is buggy (dead stores, uninitialized reads), the port reproduces
   the observable behavior and documents the quirk.
3. Progress is reported against THIS document's checkboxes and gates —
   never as a percentage, never as "almost done".
