# VICEROY.EXE — Game-logic anchor map

This is the consolidated map of independent signals that together identify
game-logic regions: the in-EXE resource-key tables, the inter-function
call graph, the per-global memory references, the RTLink overlay topology,
and the now-32 named functions covering the C runtime / map / unit-table
boundary layer. Each signal alone is noisy; together they are reliable.

Generated by hand from the outputs of:

- `tools/extract_strings.py` → `strings.json`
- `tools/asset_xref_scan.py` → `asset_xrefs.md`
- `tools/xref_strict.py`     → `strict_xrefs.json`, `hot_strings_strict.md`,
                                `anchor_drilldown.md`
- `tools/callgraph.py`       → `callgraph.json`, `callgraph.md`
- `tools/hot_globals.py`     → `per_func_globals.json`, `hot_globals.md`
- `tools/classify_funcs.py`  → `classification.json`, `classification.md`
- `tools/parse_thunks.py`    → `overlay_thunks.json`, `overlay_thunks.md`

## Signal 1 — Resource-key tables in DGROUP

### NAMES.TXT @-section table (file 0x01FB4C..0x01FC5C+)

Contiguous run of NUL-terminated section-name strings: `SEASONS`,
`UNFORESTED`, `FORESTED`, `OTHER`, `OTHER_NAMES`, `RESOURCE`, `COUNTRY`,
`NATIONALITY`, `NATIONABBREV`, `HOMEPORT`, `COLONYNAME`, `LEADERNAME`,
`MISSION`, `DIFFICULTY`, `CLASS`, `BUILDING`, `SCENARIO`, `JOB`, `CARGO`,

`LEVELS`, `TRIBES`, `FOUNDING`, `FATHERS`, `COLORS`, `INFO`, `MISC`,
`ROUTE`, …

The NAMES.TXT parser walks this table sequentially when matching
`@SEASONS`, `@COUNTRY`, etc. found in the file. Order matches NAMES.TXT
itself.

## Signal 4 — RTLink overlay topology

See `formats/RTLINK.md` and `code/VICEROY/overlay_thunks.md`.

- **Thunk table:** 1,020 thunks at `0x01A5F0..0x01D5E6` (12 KB).
- **Two thunk types:** A (variable size 10/12/14/16 bytes, with metadata trailer) and B (fixed 10 bytes, no trailer).
- **82 distinct overlay segments** referenced.
- **Top segments by entry-point density:**
  - 0x0000 (661 thunks) — main code segment, contains _main
  - 0x05EB (82 thunks) — major secondary segment
  - 0x0427 (47 thunks) — major tertiary segment
  - 0x004B (25 thunks)
  - 0x037F (24 thunks)
  - 0x0984 (16 thunks)
  - 50 more segments with 1-15 thunks each

The RTLink runtime is fully characterised at the structural level (see
PROGRESS.md "Region 0").

## Where to go next (priority order)

1. **Decode the segment-id ↔ overlay-file-offset mapping** in the overlay's directory header. Once decoded, all 1,020 thunk targets become concrete file offsets and can be added to `manual_funcs.json` as named overlay functions. This unlocks all 691 currently-RAW overlay functions (102 KB of game logic).
2. **Annotate the 13.6 KB function at 0x01D118** (was ~26 callers in original metric, now fewer because ENTER-prologue split it; RAW) — investigate whether this is still one function or many smaller ones.
3. **Annotate the 1.5 KB function at 0x01C0D6** (called 16×, RAW) — second-largest hot function in the load image.
4. **Continue system_init line-by-line** — region 1 of 4 done (~84 lines); regions 2-4 (~350 more lines) remain. Long pole.
5. **Investigate the in-overlay function at 0x01A922** (the post-thunk-table address). With the thunk table covering 0x1A5F0..0x1D5E6, this is INSIDE the table — calls "to" it are calls THROUGH the thunk system. This row is misleading and shouldn't drive annotation work.
6. **Find the NAMES.TXT parser** by tracing reads of DGROUP:0x1FB4C onward in the OVERLAY (since it's not in the load image).
7. **Identify what's at *(0x8542)** — the most-touched global (102 distinct fns). The 0x1F-byte count + 0x20-byte / 0x40-byte sub-arrays suggest a per-unit struct, current-colony struct, or current-screen struct. Annotating one of its callers should reveal which.
8. **Annotate `fclose_or_remove`** (0xF9C4, 186 bytes) — header done, per-line pending. It calls 7 other functions (very high callee count for a "small" wrapper).
9. **Annotate `load_game_state`** (0x11F6E, 403 bytes) — header done, per-line pending. The 0xAE-byte working buffer is a strong clue (matches no known struct exactly).
