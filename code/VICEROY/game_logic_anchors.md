This file is a **map of in-game text-resource keys to candidate game-logic
functions**. The keys are section headers from the COLONIZE/.TXT files
(`NAMES.TXT`, `GAME.TXT`, etc.). The runtime looks them up by name to
fetch human-readable strings or structured records (terrain, units,
buildings, founding fathers, dialog text). Functions that reference these
keys are by definition game-logic code that touches the named concept.

Generated by `tools/xref_bucket.py`. The xrefs are heuristic
(LE16-byte-match) and contain false positives, but the per-key xref counts
and per-function bucketings are still useful as starting points for
hand-annotation.

## Methodology notes

- The xref count is a heuristic LE16-byte-match — it has false positives
  from random byte coincidences but few false negatives.
- The "distinct functions" count is more reliable: if multiple xrefs from
  *different* discovered functions hit a key, the key is genuinely a
  hot game-logic anchor.
- A future refinement (`tools/xref_bucket_strict.py`) should replace the
  byte-search xref scan with a capstone-driven instruction-walk that
  flags only operand-immediate matches. That would eliminate most false
  positives.

## Use this map

When annotating a function whose offset appears in the "Distinct functions"
column for a key, suspect the function is part of that concept area and
prioritise reading its CALL/JMP targets and string operands for that
domain. For example, the 5 distinct functions referencing `COUNTRY` are
likely the nation-display / name-lookup chain.

To produce a per-key drill-down:

```bash
python tools/xref_bucket.py --exe VICEROY --text COUNTRY
```
