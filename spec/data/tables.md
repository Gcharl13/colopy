# Gameplay Data Tables (byte-anchored)

> **Layer 2 — Data Specification.** Primary-only per `/METHODOLOGY.md`.
> **Canonical primary:** `data_extracted/tables/*.json` (generated by
> `tools/build_tables.py` + `tools/extract_dgroup_tables.py` from the `.TXT`
> basis and `docs/DATA_MODEL.md`). Values are **verbatim from the game data
> files** (BYTE-EXACT); column names are the files' own `;` legends;
> `byte_anchors` cite the EXE loader/use-site where verified.
>
> §1–4 are the curated summary; **every table of every type** (all NAMES CSV +
> id→name list sections, all TRIBE dispersal tables, and the DGROUP layout
> catalog) is rendered in full in the generated block at the end of this file.

## 1. Summary
The game's numeric tables live as CSV `@`-sections in `NAMES.TXT` / `TRIBE.TXT`,
each documented by a leading `;` legend. `data_extracted/tables/names_tables.json`
+ `tribe_tables.json` hold them as named tables. This is the authoritative source
for unit/terrain/building/cargo/job/father data — **not** the reconstructed
`viceroy_source/data/*.c` (which must be verified against these).

> `@UNIT`, `@CARGO`, and `@TRIBES` are now rendered with **named columns**: their
> *special*/short entries (the non-economic goods Hammers/Crosses/Liberty Bells/
> Flags in `@CARGO`; the extra tribe names in `@TRIBES`) are shorter rows, padded
> with empty cells — no data is dropped. (`@UNIT` rows are uniform 12-field.)
