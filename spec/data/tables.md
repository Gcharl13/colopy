# Gameplay Data Tables (byte-anchored)

> **Layer 2 — Data Specification.** Primary-only per `/METHODOLOGY.md`.
> **Canonical primary:** `data_extracted/tables/*.json` (generated by
> `tools/build_tables.py` from the `.TXT` basis). Values are **verbatim from the
> game data files** (BYTE-EXACT); column names are the files' own `;` legends;
> `byte_anchors` cite the EXE loader/use-site where verified.

## 1. Summary
The game's numeric tables live as CSV `@`-sections in `NAMES.TXT` / `TRIBE.TXT`,
each documented by a leading `;` legend. `data_extracted/tables/names_tables.json`
+ `tribe_tables.json` hold them as named tables. This is the authoritative source
for unit/terrain/building/cargo/job/father data — **not** the reconstructed
`viceroy_source/data/*.c` (which must be verified against these).

## 2. Contents

| Table (`@`-section) | Columns (from the file legend) | Rows | Byte anchor |
|---------------------|--------------------------------|------|-------------|
| `@UNIT` | name, icon, movement, attack, combat, cargo, size, cost, tools, guns, hull, role, ai_role_bits | 23 | loader `@0x74EC3`: attack→`0x5236`, combat/DEF→`0x5235` (×8), guns→`0x523B`, →`0x523C` (B) |
| `@UNFORESTED` / `@FORESTED` | name, movement, defensive, improvement, value, + 9 yields (farmer/planter-s/t/c/trapper/lumberjack/ore/silver/fisherman) | 8 / 8 | auto-forest `func_006204` (file `0x6204`) (B) |
| `@BUILDING` | name, cost, tools_x10, size, min_colony, upkeep | 42 | colony build/production loader (TBD) |
| `@CARGO` | name, price_start1/2, drift_low, drift_high, burden, rise, fall, attrition, volatility | 20 | market price model; per-turn drift fn behind thunk `0x181F:0x9A4` (TBD); values (B) |
| `@JOB` | name, expert_name, student_level (4=unlearnable), europe_cost (−1=not purchasable) | 28 | profession ↔ `UnitRecord +0x15` (B) |
| `@FATHERS` | name, type, weight_1500_1600, weight_1600_1700, weight_1700plus | 25 | Congress acquisition weights by era; selection fn (TBD) |
| `@LEVELS` | tech_name, settlement_singular, settlement_plural | 5 | native settlement size tiers |
| `@TRIBES`, `@CLASS`, `@ORDERS`, `@DIFFICULTY`, `@COUNTRY`, … | (raw rows + legend; columns partially named) | — | per-section |

> `@UNIT`/`@CARGO` keep raw rows in the JSON because their *special* entries
> (e.g. Hammers/Crosses/Liberty Bells; Wagon Train) have variable column counts;
> the documented `columns` are attached as metadata. Aligning the specials is a
> depth-pass item.
